## 제주: 검색 단계 지연과 가격 필터 결함

### 검색 지연

- 원본 FAISS 파일의 실제 타입은 `IndexFlatL2`이며, 가맹점 9,346개·관광지 381개, 차원은 768이다. README의 HNSW 설명과 구분한다.
- `seed=20260915`로 저장된 가맹점 벡터 200개를 비복원 추출했다. 자연어 질문을 새로 임베딩한 평가가 아니다.
- 샘플 200개의 저장 배열과 FAISS 인덱스 내 대응 벡터를 대조해 최대 절대 오차 0을 확인했다. 모든 행의 원본 텍스트 매핑까지 검사한 것은 아니다.
- 20회 워밍업 후 질의별 가맹점 Top-9와 관광지 Top-1 검색을 측정했다.
- 원본 `load_faiss_index`를 호출해 두 인덱스를 읽고 검색하는 구간: **p50 6.5564 ms, p95 9.2900 ms**.
- 비교용으로 인덱스를 메모리에 이미 올린 검색 구간: **p50 0.6114 ms, p95 0.8142 ms**.

후자는 별도 측정 조건이지 원본 앱에 캐시 최적화를 구현했다는 뜻이 아니다. 인덱스 로딩은 OS 파일 캐시가 따뜻한 상태이며, 장비·부하·디스크 환경에 따라 변한다. 단일 측정 실행의 분포이며 운영 SLA나 RAG 전체 응답시간으로 쓰지 않는다.

### 재현한 결함

원본 `generate_response_with_faiss`를 실행하되 검색 후보를 가격구간 1~6이 포함된 9행으로 통제하고, LLM은 입력을 그대로 돌려주는 로컬 스텁으로 대체했다. 외부 호출 없이 필터 결과만 평가했다.

‘상관 없음·최고가·고가·평균 가격대·저가·최저가’ 6개 옵션 중 ‘평균 가격대’ 1개가 실패했다. 소스가 3 또는 4구간을 의도한 것으로 보이는 부분에서 아래 표현은 실제로 3구간만 검사한다.

```python
.str.startswith('3' or '4')
```

Python의 `'3' or '4'`는 `'3'`이므로, 제어된 후보에서 기대했던 4행 중 3구간 2행만 반환하고 4구간 2행은 누락했다. 이 결함은 **미수정** 상태다. 5/6을 맛집 추천 정확도 83.3%로 바꾸어 쓰지 않는다.

## Stay-view: 54개 화면 데이터 조합 검증

공개 CSV의 9개 지역 × 소음·가격·위치·서비스·청결·편의시설 6개 항목을 모두 검사했다. 원본 앱의 `sorted_hotels`와 `top_hotels` 대입문을 AST로 가져와 실행했다. Streamlit UI 자체는 구동하지 않았다.

각 조합에서 다음을 검사해 54개 조합 모두 통과했다.

- 반환 호텔명이 중복되지 않는지.
- 해당 지역의 고유 호텔 수와 Top-5 제한에 맞는 행 수인지.
- 점수가 내림차순인지.
- 다른 지역 호텔이 섞이지 않는지.
- 호텔별 최고 점수를 독립 집계했을 때 상위 5개 점수와 일치하는지.

이는 원본 리뷰의 사실 보존·요약 오류·사용자 선택 시간 측정이 아니다. 해당 평가에는 원본 리뷰와 정답 기준이 추가로 필요하다.

## 노후애: 192개 경계값 시나리오

원본 데이터 전처리·규칙 필터·벡터화·FAISS 검색·결과 조합 함수를 수정 없이 실행했다. CSV는 메모리에 미리 로드했고, 전처리 함수 내부의 난수 시드는 원본대로 42다. 모델 pickle, TabNet 추론, 앱 UI는 실행하지 않았다.

입력 조합을 측정 전에 다음과 같이 고정했다.

- 추천 화면의 3개 위험성향: 안정형·위험중립형·공격형.
- 투자금액(만원) 8개: 0, 99, 100, 499, 500, 999, 1000, 5000.
- 투자기간(개월) 8개: 0, 5, 6, 11, 12, 23, 24, 36.
- 목표 월이자 입력은 3으로 고정. 함수 경계 검사를 위해 실제 UI 범위 밖 입력도 포함했다.
- 3 × 8 × 8 = 192개. 입력 실행 순서의 난수 시드는 20260915.

결과:

- **192개 시나리오 모두 검사 통과**.
- 실제 추천을 반환한 경우 **102개**, 반환된 추천 합계 **252건**. 같은 상품이 다른 시나리오에 다시 나타날 수 있어 고유 상품 수가 아니다.
- 후보가 없는 경우 **90개**. 독립적으로 조건 충족 후보 수를 집계해, 빈 결과를 무조건 성공으로 처리하지 않았다.
- 반환 추천의 금액·기간·소스 정의 위험성향 규칙 위반 **0/252건**.
- 유형별 최대 개수(예·적금 2, 펀드 1), 전체 최대 3개, 상품명 중복 여부도 함께 검사했다.
- 전처리·필터·검색 함수 구간 **p50 18.2371 ms / p95 26.0594 ms**. 디스크 읽기·TabNet·UI·네트워크 제외.

위험성향 허용 규칙은 실제 금융 적합성의 정답이 아니라 이 프로토타입 코드가 정의한 규칙이다. 일부 속성은 난수로 보완되므로 실제 금융상품의 가입 조건·수익률·추천 품질을 검증한 결과로 쓰지 않는다.

## 아직 측정할 수 없는 항목

- **또박톡 WER 재평가**: 파인튜닝 가중치와 정답 전사가 있는 평가 음성이 필요하다. 공개 저장소의 설정·토크나이저만으로는 재현할 수 없다. 기존 21.2%를 이번 측정 결과로 취급하지 않는다.
- **제주 자연어 조건 충족률 / Stay-view 요약 사실성**: 별도의 질의·정답 판정 또는 원본 리뷰가 필요하다. 이번 제어된 기능 검사와 혼동하지 않는다.
- **LXP 실제 응답시간·비용 감소**: 개발용 실행 환경과 외부 모델 호출 조건을 정한 별도 측정이 필요하다. 이번 캐시 카운터 테스트에서 환산하지 않는다.
- **FitBuddy 자세 판정 성능**: 실행 가능한 모델과 기준 라벨이 있는 동작 영상이 필요하다. 이번에 새 성능 수치를 만들지 않았다.
