KoBART로 1차 요약한 뒤 Gemini로 문장을 다듬는 2단계 방식을 제안하고 적용했습니다. 정리된 내용을 핵심 3줄로 제공하고 항목별 비교 화면과 연결했습니다.
결과
2단계 요약 결과를 숙소 비교 화면에 반영했습니다. 공개 화면에는 9개 지역의 긍정 및 부정 요약문 780건이 연결돼 있으며, 별도의 요약 품질 개선율을 측정한 것은 아닙니다.

배운 점: 요약을 짧게 만드는 것과 선택에 도움이 되게 만드는 것은 달랐습니다. 읽을 수 있는 문장과 숙소를 비교할 공통 기준을 함께 구성했습니다.

GitHub 구현 화면 2025.07 ~ 2025.08 (2개월)

프로젝트 소개

시니어마다 다른 재무 상태와 투자 조건에 맞는 금융상품 탐색을 돕는 프로젝트입니다. 상품 분류 기준을 재정리하고 설문 기반 재무 유형 진단과 조건별 상품 추천을 연결했습니다.

팀 규모: 3명

담당 역할: 상품 데이터 전처리와 위험도 및 안정성 기준의 재분류, TabNet 모델 학습, FAISS 추천 검색의 설계와 구현을 맡았습니다.

Python TabNet FAISS Streamlit
문제 정의
기획 자료에서 고령층 내부의 자산 격차와 연금 및 예적금 중심의 노후 준비에 주목했습니다. 은퇴 이후에는 자산 보전과 생활비 마련 등 복합적인 수요가 생기므로, 시니어를 하나의 집단으로 보기보다 개인의 자산과 소득, 투자성향을 반영한 재무 관리가 필요하다고 판단했습니다.
문제해결
개인의 재무 상태와 투자 조건을 함께 반영하기 위해 설문 기반 TabNet 유형 분류와 조건 필터를 분리하고 FAISS 상품 검색에 연결했습니다. 서로 다른 상품군을 비교할 수 있도록 위험도와 안정성을 기준으로 다시 분류했습니다.
결과
공시 원본 10,720행을 상품명 기준 10,036건의 검색 후보로 정리했습니다. 재무 유형 진단과 투자 조건 필터를 연결해 예적금 최대 2개와 펀드 최대 1개를 추천하도록 구현했습니다. 합성 사용자와 일부 누락 속성의 시뮬레이션 값을 활용했습니다.

트러블슈팅 상품군마다 다른 분류 기준의 통합

배경
적금과 예금 등 상품군마다 분류 기준이 달라 원본 범주만으로는 상품 특성을 같은 기준에서 비교하기 어려웠습니다.
분석
데이터 형식을 맞추더라도 상품군별 범주가 뜻하는 바가 다르면 통합 비교 기준이 되지 않습니다. 추천 모델에 연결하기 전에 범주의 의미를 정리해야 했습니다.
해결
위험도와 안정성을 기준으로 상품을 다시 카테고리화했습니다. 재무 유형 분류와 투자 조건 필터를 분리하고 금액과 수익률, 기간을 공통 벡터로 구성했습니다.
결과
상품명 기준 10,036건의 검색 후보를 구성하고 조건을 통과한 후보 안에서 최대 3개 상품을 추천하도록 구현했습니다. 합성 사용자와 일부 누락 속성의 시뮬레이션 값을 활용했습니다.

배운 점: 통합의 기준은 같은 이름의 컬럼이 아니라 데이터가 뜻하는 의미였습니다. 서로 다른 상품 분류를 해석하고 공통 기준을 만드는 전처리 경험을 쌓았습니다.

배운 점: 이 프로젝트에서는 PM과 인프라 역할로 참여하며 기능의 구현 내용과 실행 환경을 함께 바라봤습니다. 팀이 구현한 기능과 제가 직접 맡은 범위를 구분해 정리했습니다.
