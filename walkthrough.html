Samsung Academy LXP 구축 및 공개 서비스 리뉴얼

외주 프로젝트

2026.07 — 2026.10 (4개월 예정) (진행중)

교육 운영 현황 파악과 과정 탐색의 어려움을 해결하기 위한 프로젝트입니다. 백엔드와 인프라 구성, AI 학습지원 연동을 맡아 교육 운영 기능과 학습지원 서비스를 연결했습니다.

팀 규모: 2명

담당 역할: 백엔드: Java/Spring Boot와 JPA 기반 시험, 평가, 설문 및 이수 관리 기능 개발. Spring Security로 역할별 권한과 강사의 담당 과정별 접근 범위 적용.인프라: 배포 경로와 Cloudflare 정적 자산 캐시 관리, 협업 브랜치 관리 및 JUnit 회귀 테스트.AI 연동: Claude API 기반 학습자료 질의응답과 학습 로드맵 연결. 답변 출처 처리, 결과 캐싱과 사용자별 사용량 제어 구현.

아래 화면은 전체 담당 범위 중 대시보드와 AI 학습지원의 일부입니다. 담당 업무와 주요 성과 보기

AI 학습 Q&A pipeline

모델, 핵심 처리
01, INPUT훈련생 질문과정 안에서 최대 1,000자 입력
02, GUARD호출 전 검사수강 권한, 자료 유무, 일일 한도 확인
03, CONTEXT과정 자료 구성PDF 본문과 질문을 컨텍스트로 조합
04, GENERATE근거 기반 답변자료 범위 안에서 답변과 인용 생성Claude API
05, OUTPUT답변 또는 강사 이관유효 인용만 노출, 미해결 질문 자동 등록

모델 호출 전에 권한과 사용량을 차단하고, 생성 뒤에는 실제 자료 범위를 벗어난 인용 번호를 다시 제거합니다.

01질문 입력: 훈련생이 학습 중 질문을 남긴다.

02호출 전 검사: 수강 권한, 입력 길이 1,000자, 과정 자료 유무, 일일 한도(전체 500 / 1인 50)를 모델을 부르기 전에 확인한다. 하나라도 걸리면 모델을 호출하지 않는다.

03자료 기반 답변: 과정 자료(PDF 본문 포함)를 컨텍스트로 Claude API를 호출하고, 답변이 실제 인용한 자료만 링크로 붙인다. 범위 밖 인용 번호는 버린다.

04미해결 질문 이관: 해결되지 않은 질문은 담당 강사 Q&A로 자동 등록되어 사람에게 이어진다.

운영 주소 lms.samsungax.com: 훈련생 계정이 있어야 접속할 수 있어 위 화면으로 대신한다.

데이터분석기반 AI 프로젝트 공모전 또박톡

우수상

2025.09 ~ 2025.11 (3개월)

팀 규모: 4명

고령층이 의료 및 공공 상담을 이해하도록 돕는 프로젝트입니다. 음성 인식 모델을 파인튜닝하고 쉬운 말 변환을 연결해, 상담 내용을 외부 전송 없이 자막과 요약으로 제공했습니다.

실시간 자막 화면에서 파란 글씨를 누르면 쉬운 말로 다시 들려준다: 식후 → 밥 먹은 뒤, 복용 → 드세요. 요약 화면의 할 일에는 각각 복약 알림이 붙는다.

Private speech pipeline

모델, 핵심 처리
01, INPUT실시간 대화 음성고령 사용자와 상담 상대의 발화
02, STT노인 음성 전사의료 키워드 가중 학습, WER 21.2%Whisper
03, DIARIZE화자 분리1.2초 창 + 최근 5회 다수결Resemblyzer
04, SIMPLIFY쉬운말 실시간 변환전문용어를 고령층 친화 표현으로 치환
05, LOCAL LLM요약, 할 일, 알림대화 종료 후 기기 안에서 구조화Ollama

진료 및 복약 데이터가 외부로 나가지 않도록 전사 이후 요약까지 로컬에서 처리하며, 실시간 자막과 종료 후 요약을 분리했습니다.

01실시간 전사: AI Hub 노인 음성으로 파인튜닝한 Whisper가 말을 텍스트로 바꾼다. 의료 키워드에 가중치를 준 샘플링으로 학습해 WER 21.2%를 얻었다.

02화자 분리: Resemblyzer가 나와 상대를 구분한다. 1.2초 슬라이딩 윈도우와 최근 5회 판정 다수결로 순간 오판을 평탄화한다.

03쉬운말 변환: 전문용어를 쉬운 표현으로 바꾼다. 전사 정확도와 용어 변환을 한 모듈에서 처리하면 서로 간섭해 별도 단계로 분리했다.

04요약과 체크리스트: Ollama가 대화를 요약해 할 일, 필요한 물건, 복약 시간으로 구조화하고 알림으로 연결한다.

＊외부 API를 쓰지 않은 이유: 요약과 쉬운말 변환은 클라우드 LLM이 품질도 속도도 낫다. 그럼에도 로컬에 Ollama 서버를 띄워 붙인 것은, 이 서비스가 다루는 내용이 진료 내용과 복약 지시이기 때문이다. 응답 속도를 양보하는 대신 음성과 대화가 기기를 벗어나지 않는 구조를 택했다. 요약은 통화가 끝난 뒤 처리라 실시간성이 덜 중요했던 점도 함께 고려했다.

제12회 AI·데이터 분석활용 빅콘테스트 경진대회 어서 와용

생성형AI 분야, 본선 진출

2024.10 ~ 2024.11 (2개월)

팀 규모: 4명

여행자의 상황에 맞는 제주 맛집 탐색을 돕는 프로젝트입니다. 가맹점 데이터를 정리하고 테마별 조건을 RAG에 연결해, 사용자 질문과 선택 조건을 반영한 추천 답변을 제공했습니다.

RAG search pipeline

공개 코드 기준
01, INPUT자연어 질문 + 조건가격대, 위치, 업종, 현지인 비중
02, RETRIEVE의미 기반 후보 검색질문 임베딩 → 유사 가맹점 탐색Ko-SRoBERTa, FAISS
03, TOUR관광지 별도 검색관광지 381건 중 유사 후보 1건FAISS
04, FILTER가격대 필터선택한 이용금액 구간으로 후보 축소
05, GENERATE검색 근거로 답변선별된 가맹점 정보만 컨텍스트로 전달Gemini 1.5 Flash
06, OUTPUT맛집 + 추천 이유가맹점, 관광지 정보를 활용한 답변

가맹점 월별 원본 67,575행에서 가맹점명별 최신월 9,346건을 선별합니다. 가맹점과 관광지를 각각 검색하고 가격대 필터를 적용한 결과를 LLM에 전달합니다.

01의미 검색: 가맹점명 기준 9,346건의 768차원 임베딩을 사용한다. 질문을 Ko-SRoBERTa로 변환하고 FAISS에서 기본 후보 9건을 검색한다.

02관광지 검색: 관광지 381건의 별도 임베딩, 인덱스에서 질문과 유사한 관광지 1건을 검색한다.

03가격대 필터: 검색된 가맹점 후보에 사용자가 선택한 건당평균이용금액구간을 적용한다.

04검색 근거를 활용한 답변: 선별된 가맹점과 관광지 텍스트를 Gemini 1.5 Flash에 전달해 추천 답변을 생성한다. 실제 도로 이동시간이나 추천 정확도를 검증한 결과는 아니다.

머신러닝/딥러닝 프로젝트 공모전 Stay-view

대상

팀 규모: 3명

숙소 리뷰의 장단점을 같은 기준으로 비교하기 위한 프로젝트입니다. 숙소 선택에 공통된 판단 기준을 설정하고 리뷰를 분석해, 관심 항목별 점수와 요약을 함께 확인하는 비교 화면을 구현했습니다.

Review intelligence pipeline

모델, 핵심 처리
01, DATA호텔 리뷰 전처리크롤링 후 불용어와 노이즈 제거
02, ANALYZE감성, 토픽 분해긍정과 부정 판별 + 6개 평가 항목 분류KoBERT, LDA
03, SUMMARIZE1차 압축 요약리뷰 묶음에서 핵심 문장 추출KoBART
04, REFINE3줄 요약 정제뭉개진 문장을 읽기 쉽게 재구성Gemini
05, OUTPUT호텔 비교, Top-59개 지역, 호텔 요약 데이터 394행

리뷰 분석, 요약은 사전 처리 단계입니다. 공개 앱은 결과 CSV 394행에서 9개 지역의 긍정 요약 394건, 부정 요약 386건, 총 780건과 6개 항목 점수를 표시합니다. 요약문 수는 원본 리뷰 수와 구분합니다.

01배포 데이터: 긍정 및 부정 요약, 6개 항목 점수, 주소, 좌표를 포함한 호텔 요약 데이터 394행을 CSV로 로드한다.

02감성 + 토픽 분해: KoBERT로 긍정과 부정을 판별하고 LDA로 6개 항목에 자동 분류한다.

032단계 요약: KoBART로 1차 요약한 뒤 Gemini로 다시 다듬어 핵심 3줄로 줄인다. 1차 요약만으로는 문장이 뭉개져 2차를 얹었다.

04항목별 비교: 지역과 정렬 항목을 선택하면 점수순으로 정렬하고 호텔명 중복을 제외해 Top-5를 표시한다. 지도와 길찾기 링크로 위치도 확인할 수 있다.

시니어 재무 진단과 맞춤 금융상품 추천 서비스 노후애

팀 프로젝트

2025.07 ~ 2025.08 (2개월)

팀 규모: 3명

담당 역할: 상품 데이터 전처리와 위험도 및 안정성 기준의 재분류, TabNet 모델 학습, FAISS 추천 검색 설계 및 구현

시니어마다 다른 재무 상태와 투자 조건에 맞는 금융상품 탐색을 돕는 프로젝트입니다. 상품 분류 기준을 재정리하고 설문 기반 재무 유형 진단과 조건별 상품 추천을 연결했습니다.

Finance recommendation pipeline

모델, 핵심 처리
01, INPUT9문항 설문연령, 소득, 자산, 투자성향
02, CLASSIFY재무 유형 진단6개 세그먼트 분류 + 판단 근거 산출TabNet
03, FILTER투자 조건 필터투자금, 기간, 성향 → 유형별 후보
04, RANK유사 상품 탐색예적금 최대 2개 + 펀드 최대 1개FAISS, L2
05, OUTPUT맞춤 상품 추천조건에 맞는 최대 3개 상품 제시

상품마다 달랐던 분류 기준을 위험도와 안정성 중심으로 재정리했습니다. 공시 원본 10,720행에서 상품명 기준 중복과 누락을 정리해 예적금 440건, 펀드 9,596건, 총 10,036건의 후보를 구성합니다. 합성 사용자 데이터와 일부 누락 속성의 시뮬레이션 값을 사용했습니다.

01설문 입력: 나이, 가구원수, 피부양자, 금융자산, 투자성향 등 9문항을 단계별로 받는다. 한 화면에 한 문항씩 두고 진행률을 표시한다.

02재무 유형 진단: 연금, 소득, 자산, 지출 기준으로 정의한 6종 세그먼트(위험취약형, 자산운용형, 균형형, 고소비형, 연금의존형, 자산의존형) 중 하나로 분류한다. TabNet을 쓴 이유는 개인별 feature attribution이 남아 어떤 항목이 그 판정을 만들었는지 설명할 수 있기 때문이다.

03조건 필터링: 투자금액, 기간, 위험성향 조건을 적용하고 예상 수익률 기준으로 유형별 최대 500개 후보를 남긴다.

04유사도 추천: 최소투자금액, 예상수익률, 권장투자기간을 3차원 벡터로 구성한다. FAISS IndexFlatL2로 예적금 최대 2개와 펀드 최대 1개를 각각 검색해 합친다.
